# Аудит демо-, fallback- и захардкоженных данных

## Итог

В отслеживаемых исходниках не найдено бинарников эталонного проекта, готовых изображений его страниц или JSON с готовой реальной трассой. `git ls-files` не показал отслеживаемых PDF/DWG/DXF/XLSX/PNG/JPG/ZIP и файлов `docs/benchmark/`. Есть тест `confidentiality.test.ts`, запрещающий старый `realProjectData`/`demo-derived` источник.

Однако в коде присутствуют четыре разных класса констант:

1. намеренно синтетические демо-данные;
2. инженерные/normative defaults, требующие подтверждения;
3. алгоритмические коэффициенты и параметры листов;
4. ссылки на конкретный приёмочный объект в локальных тестах/документации.

Их нельзя считать одинаковыми по риску.

| `engine/src/demo.ts` | искусственная поверхность, 40 зданий, источник, геология | Допустимо для UI/unit-тестов; помечено synthetic. Не должно разрешать финальный выпуск. |
| `engine/src/demoStorm.ts` | искусственная ось 2400 м, шаг 100 м, притоки, отметки | Допустимо; прямо заявлено, что не связано с конфиденциальным объектом. |
| `frontend/src/shared/stormDemo.ts` | synthetic corridor, каталог, скважины, survey | Допустимо; сохраняется с `synthetic`/`synthetic-demo` provenance. |

Положительный контроль: BasisSection сообщает, что synthetic demo не содержит реальных исходных документов и не разрешает инженерный выпуск.

## Макеты и незавершённые fallback-функции

- `cloudConvertProvider`: объявлен, но readiness всегда false, convert бросает `not implemented`.
- `vgskSource`: `available: false`, формат внешней базы отсутствует.
- PDF OCR: отсутствует, цифровой text layer является обязательным.
- `runFullPipeline` для В1 использует fallback `traceNetwork`, который не знает всех генпланных препятствий.
- В `persistEquipment` без sizing давление оценивается формулой `45 + перепад рельефа`; это честный fallback, но его нельзя использовать как окончательное давление проекта.
- `trace.interpolateElevation` возвращает 0 при полном отсутствии survey. Строгий К1/К2 путь блокирует отсутствие рельефа, но низкоуровневая функция сама по себе допускает физически неверный ноль.

## Имеющиеся anti-hardcoding проверки

1. Отсутствие `realProjectData.json` и запрещённых маркеров в product source.
2. Динамическое количество страниц рабочего альбома.
3. Канонический пикетаж берётся из профиля; секционные планы не подменяют его длиной экранной полилинии.
4. Fingerprint меняется при изменении профиля, топографии, полной геометрии сети/ограничений или геологии без изменения числа строк.
5. Рабочий и сводный планы блокируются при отсутствии фактических alignment вместо молчаливого соединения концов.
6. Ведомости и спецификации имеют непересекающиеся `dataRange`, а отдельная серия спецификации пагинируется по числу строк.
7. Финальный выпуск блокируется при неполных источниках.

## Недостающие anti-hardcoding проверки

- изменение координаты в реальном DWG должно менять геометрию плана и длины;
- изменение отметки topography должно менять профиль/земляные работы;
- изменение геологии должно менять основание/водопонижение/спецификацию;
- изменение диаметра должно синхронно менять план, профиль и XLSX;
- генерация на втором проекте с другим CRS/масштабом;
- поиск совпадающих растровых фрагментов эталона в bundle/PDF;
- проверка отсутствия project-specific labels/coordinates в production JS;
- чувствительный анализ и документирование route penalty constants.

## Рекомендация

Разделить конфигурацию на три явных слоя:

1. `syntheticDemoConfig` — только UI/тесты, никогда не final;
2. `engineeringMethodConfig` — версия алгоритма, документированные штрафы и пределы;
3. `projectInputSnapshot` — все площадочные и нормативные значения с provenance и подтверждением.

Финальный расчёт должен отклонять любой unresolved default вместо бесшумного использования.
