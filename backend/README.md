# Backend (Supabase)

Проект Supabase: `dqeejdtwwwisptkexchj`.

## Схема данных

| Таблица | Назначение |
| --- | --- |
| `profiles` | Профиль пользователя, создаётся автоматически при регистрации (триггер на `auth.users`) |
| `projects` | Проекты водоснабжения, принадлежат пользователю (`owner_id`) |
| `datasets` | Загруженные исходные данные: топосъёмка, здания, источник, геология, сейсмика, нормативы |
| `buildings` | Здания-потребители: координаты, этажность, жители |
| `nodes` | Узлы сети: источник, узловые точки, гидранты, задвижки, вантузы, выпуски, колодцы |
| `pipes` | Участки сети: узел начала и конца, длина, диаметр, материал |
| `calc_runs` | Запуски гидравлического расчёта: статус, параметры, сводка результатов |
| `exports` | Сгенерированные документы: DXF, PDF, XLSX (файлы лежат в Storage) |

Storage: приватные бакеты `source-files` (исходники) и `exports` (результаты).
Путь файла: `{user_id}/{project_id}/{имя файла}`.

RLS: включён на всех таблицах. Доступ к строкам имеет только владелец проекта
(функция `is_project_owner`). В Storage пользователь видит только свою папку.

## Как применить миграцию

1. Откройте Supabase Dashboard -> SQL Editor -> New query.
2. Скопируйте содержимое `migrations/0001_init.sql`, вставьте, нажмите Run.
3. Должно завершиться без ошибок (Success. No rows returned).

## Настройка Auth

Authentication -> Sign In / Providers -> Email: провайдер включён по умолчанию.
Для хакатона отключите Confirm email, иначе регистрация будет требовать
подтверждения по почте, а встроенный SMTP Supabase сильно ограничен по числу писем.
